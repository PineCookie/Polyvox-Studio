# Polyvox Studio

[English](README.md) | 简体中文

用你自己的录音训练语音合成（TTS）音色并直接使用——全部在本机的一个网页应用里完成。
Polyvox Studio 把原始音频整理成干净的数据集，在
[VoxCPM2](https://github.com/OpenBMB/VoxCPM)、
[dots.tts](https://github.com/rednote-hilab/dots.tts) 或
[GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) 上微调音色，再用它合成语音。

界面支持简体中文和英文。

## 亮点

- **三种 TTS 模型，一套流程。** VoxCPM2 和 dots.tts（LoRA 训练，48 kHz），以及
  GPT-SoVITS v2Pro、v2ProPlus 和 v4（音色训练）。数据集准备一次，就能训练任意一种模型；
  各模型的音色并列在同一个列表里。
- **从几小时的原始音频到数据集。** 指向录音（WAV、FLAC、mp3、m4a，甚至视频文件）或现有的
  标注列表即可。长录音借助语音识别和强制对齐在词与词之间切开，没有文本的片段自动转写；
  还可以先去除音乐、混响或噪声。
- **逐条检查每个片段。** 文本与音频对不上、字被截断、混进了别人的声音、音频削波或是在唱歌、
  首尾有多余的声音——这些片段都会被标记出来。按问题从重到轻逐条审阅：试听、改文本、裁剪或删除。
- **训练过程看得见。** 损失曲线、每个检查点的试听样本，以及说话人相似度评分——直观显示每个
  检查点有多像目标声音。任何训练任务都能停止、继续、加训；一键试听检查点。
- **默认设置就好用。** 新建训练会按数据集大小确定训练长度，并使用能自行找到学习率的
  Prodigy Schedule-Free 优化器。批大小按显存（8、12、16 GB 及以上）自动调整。
- **比模型官方代码更快，结果不变。** dots.tts 合成快约 4 倍，GPT-SoVITS 快约 2.5 倍；
  切换 VoxCPM2 或 dots.tts 音色只需约 1 秒，无需重新加载模型。训练每步快约 1.6 倍（VoxCPM2）
  到 3 倍（dots.tts），VoxCPM2 训练显存减半。详见[速度](#速度)。
- **兼容 GPT-SoVITS。** 可以导入在 GPT-SoVITS 网页界面中训练的音色；在这里训练的音色也能在
  GPT-SoVITS 网页界面中加载。
- **分享音色**：导出为小巧的 zip 包，不含本地路径、日志和数据集音频；导入只需一键。
- **安装简单。** 一条命令；[uv](https://docs.astral.sh/uv/) 会自动安装 Python、PyTorch
  及其他一切依赖。无需安装 FFmpeg。支持 Windows 和 Linux。

## 快速开始

1. 安装 uv：

   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"   # Windows
   curl -LsSf https://astral.sh/uv/install.sh | sh                                       # Linux
   ```

2. 从[最新版本](../../releases/latest)下载 `.zip`（Windows）或 `.tar.gz`（Linux），解压后在
   文件夹中运行 `run.bat`（Windows）或 `./run.sh`（Linux）。首次启动会安装所有依赖，需要几分钟。
3. 打开 http://127.0.0.1:8808 ，在「模型」页下载 **VoxCPM2**（约 5 GB）。其他模型等需要时再下载
   （见[模型](#模型)）。在中国大陆可以在「模型」页选择 hf-mirror.com 镜像。
4. 在「合成」页输入文字，点击「生成」。模型加载后的第一次生成需要约 30 秒用于编译，之后就很快了。

推荐使用 8 GB 及以上显存的 NVIDIA 显卡，见[运行要求](#运行要求)。

## 使用流程

1. **准备**数据集：「新建数据集」，然后用「添加来源…」指定一个文件夹或标注列表，再点
   「运行剩余的步骤」。浏览被标记的片段，修正或删除有问题的。
2. **训练**音色：在数据集页面点「用它训练」，选择模型后开始。检查点陆续生成时，查看曲线、试听样本。
3. **合成**：训练好的音色会出现在「音色」列表中。选中它（也可以选一个检查点），输入文字，生成。

## 合成

「音色」面板按模型分组列出基础模型和所有训练过的音色；有多个检查点的音色可以选择其中一个。然后：

- **文本**：VoxCPM2 的非语言标签（笑、叹气……）一键插入。
- **风格**（VoxCPM2）：描述想要的声音，例如“沉稳温柔的女声，语速较慢”。
- **参考音频**：从一段音频克隆声音；再填上它的文本（点「识别」自动填写）通常会更像。
- **高级**：引导强度、步数、种子以及各模型自己的设置。
- **历史记录**：保存本次会话生成的音频，方便对比和下载。

GPT-SoVITS 总是根据一段参考音频说话：它的每个音色都有一段默认参考音频（从训练数据中挑选），
可以在「音色」面板中更换。

## 准备数据集

「数据集」页把原始录音和标注列表整理成数据文件夹中的数据集。「新建数据集」创建一个空数据集；
在它的页面上，「添加来源…」接受本机上的一个路径：

- GPT-SoVITS 的 `.list`（`路径|说话人|语言|文本`），
- `文件|文本` 格式的 CSV（LJSpeech 风格），
- `.jsonl` 清单，或
- 一个音频文件夹，可以带同名的 `.txt` / `.lab` 文本，也可以不带。

标注列表里的路径常常已经失效（来自另一台电脑，或文件夹被移动过）。每个片段会依次按原路径、
按文件名在列表旁边及其 `wavs/` 文件夹中、按文件名在可选的音频文件夹中查找。「扫描」会在写入
任何内容之前显示找到了什么；找不到音频的行会被跳过。片段写入 `data/<名称>/train.jsonl`，默认
复制到 `data/<名称>/wavs/`，让文件夹自成一体。长录音（超过 20 秒）记录在
`data/<名称>/dataset.json` 中，切分前保留在原处。随时可以继续添加来源；已在数据集中的音频会被跳过。

页面按顺序列出数据集的步骤：「来源」「清理」（可选）「切分录音」「转写」「检查片段」和「整理」。
每个步骤都会显示还有多少内容需要处理（数据集可能混合了长录音和现成的片段，也可能做到一半停了），
记住上次的设置，只处理剩下的部分，并边做边保存，中途停止也损失很少。「运行剩余的步骤」按顺序
运行需要的步骤；「添加来源…」可以在添加后立即开始。步骤在后台运行，显示进度，可以取消。

**切分。** 长录音每次读取 10 分钟，几个小时的音频也没问题。语音活动检测（Silero VAD）找出
语音，Qwen3-ASR 转写，强制对齐模型定位每个词。只在词与词之间、真正的停顿处切开，优先切在句末，
并让片段长度保持在设定范围内（默认 2–15 秒）；每个片段都保留对应的那一段文本，包括标点。

**转写。** 没有文本的片段会保留下来，「转写」步骤用 Qwen3-ASR 补上文本，可以指定语言以及需要
写对的人名、术语；转写之前它们不参与训练。转写过的片段列在 `data/<名称>/asr.json` 中，方便审阅。

**删除。** 数据集页面上的「删除…」会先列出将被删除的内容（片段、大小、用过它的训练任务），
确认后才删除文件夹。

### 可选清理：人声分离、去混响、降噪

「清理」步骤使用 UVR5 和 MSST-WebUI 所用的 RoFormer 模型（模型结构取自 ZFTurbo 的
Music-Source-Separation-Training，MIT 许可）：从音乐和背景中**分离人声**、**去混响**、**降噪**。
每一项默认关闭，下载对应模型（「模型」页）后可用。片段原地处理；长录音在切分时处理。
去混响模型的权重为 GPL-3.0 许可。

默认的人声模型是 “bleedless” 型：对训练数据来说，人声里残留音乐比人声稍微单薄更糟糕。人声分离
会增加耗时并带来细微的瑕疵，所以只用于音乐或背景声压在人声下面的录音，干净的录音不需要。
它不会去除歌声。

任何 MSST 格式的模型都可以使用：把 `POLYVOX_VOCALS_MODEL`、`POLYVOX_DEREVERB_MODEL` 或
`POLYVOX_DENOISE_MODEL` 设为 `model.ckpt`（配置文件为旁边同名或唯一的 `.yaml`）或
`model.ckpt|config.yaml`。

### 检查片段

强制对齐会在音频中定位文本的每个词。「检查片段」步骤以此为主，结合其他几项检测，标记需要审阅的
片段（只检查新片段和改过文本的片段；「全部重新检查」会重做所有片段）：

| 标记 | 含义 |
|---|---|
| 唱歌 | 唱歌的片段（K 歌、翻唱）：不适合作为训练数据 |
| 其他声音？ | 声音与数据集其余部分不像：可能是嘉宾或播放的音频 |
| 削波 | 波形在峰值处被削平（录音或保存时音量过大） |
| 不匹配 | 文本有一部分与音频对不上 |
| 缺词？ | 语音识别听到了文本里没有的词（需开启「与语音识别对比」） |
| 语气词？ | 文本中的语气词或笑声（嗯、哈哈、呵呵……）落在安静的音频上：可能并没有说 |
| 边缘声音 | 在文字之前或之后、隔着停顿的声音（叹气、嗯、笑声，或文本漏掉的词） |
| 未转写 | 紧挨着已对齐文字的语音：文本可能漏了内容 |
| 边缘截断 | 文件开头或结尾处声音仍然很响：可能有字被截断 |
| 静音过长 | 语音之后超过 0.5 秒的静音（模型据此学习何时停止），或之前超过 1 秒 |

可选两种对齐模型：**Qwen3-ForcedAligner**（11 种语言，支持混合文字）和 **wav2vec2 CTC** 模型
（对单个错字更敏感；默认为中文模型，其他语言可设置 `POLYVOX_CTC_ALIGN_MODEL`）。文本漏掉几个词时，
对齐通常发现不了，所以「与语音识别对比」会把每个片段重新识别一遍，并标记「缺词？」。唱歌检测
（AudioSet 音频标注模型）默认关闭：它会拖慢检查，而且大多数数据集里没有歌。结果保存在
`data/<名称>/align.json`。

「整理」步骤裁剪首尾（过长的静音，以及隔着停顿的叹气或“嗯”，保留 0.15 秒），并可以把所有片段
调到同一响度。标记为「不匹配」或「缺词？」的片段留待审阅，不会自动裁剪。片段原地改写；原始文件
保存在清单旁边的 `originals/` 中。

### 审阅片段

片段表格可以只显示被标记的片段，并按问题从重到轻排序。每一行显示片段的波形，文本覆盖的部分带阴影；
点击波形可从该处播放。打开一个片段，可以看到对齐模型把每个词放在了哪里（不确定的词会标出），并且可以：

- 「编辑」文本（或「使用识别结果」）；保存后会重新检查这个片段。
- 「裁剪…」：拖动波形上的手柄，松开时会播放新的边缘。
- 「重新检查」，或用「语音识别」与识别结果对比。
- 「删除」：片段仍留在表格中（变暗），但训练时会排除它（记录在 `data/<名称>/excluded.json`）；
  「恢复」可以把它找回来。

「全部裁剪」会裁剪所有标记为「边缘声音」或「静音过长」的片段（表格中以灰色显示将被裁掉的部分）；
只显示某一种标记时，「全部删除」会删除所有带这个标记的片段，例如所有唱歌的片段。

关于语气词和笑声：对训练来说，个数不如一致性重要，所以「转写」步骤会把每条文本中连续重复的同一个
语气词缩短（哈哈哈哈 → 哈哈，嗯嗯嗯 → 嗯嗯；默认开启）。不同的语气词保持不同（“哈哈”是笑，
“呵呵”是另一种声音），文本中保留普通汉字，而不是 `[laughing]` 这样的标签——标签可能带来多余的声音。

### 导出给其他 TTS 工具

数据集页面上的「导出给其他 TTS」会按其他工具的格式写出训练片段（已删除的除外），默认写到
`data/` 旁边的 `exports/<数据集>_<格式>`：

| 格式 | 文件 |
|---|---|
| GPT-SoVITS | `<说话人>.list`：`路径\|说话人\|语言\|文本`，语言 `zh` / `ja` / `en` / `ko` 按每条文本的文字判断（或统一指定） |
| LJSpeech | `metadata.csv`：`id\|text\|text` |
| CSV（F5-TTS） | 带 `audio_file\|text` 表头的 `metadata.csv` |
| Kaldi | `wav.scp`、`text`、`utt2spk`、`spk2utt` |
| 文件夹 | `wavs/<id>.wav` 及 `wavs/<id>.lab` |

音频以简单编号命名、WAV 格式写入 `wavs/`，直接复制或重采样；可以设置片段长度范围，排除范围外的
片段（GPT-SoVITS 建议 1–15 秒）。

## 训练

「训练」页可以开始、停止和继续训练任务，一次运行一个。「新建训练」从一个数据集开始（显示它的
统计、警告和可浏览的片段），然后选择模型和训练设置；任务名会根据数据集和模型自动建议。

| 模型 | 训练什么 | 默认设置 |
|---|---|---|
| VoxCPM2 | 语言模型和扩散解码器上的 LoRA（秩 32） | 4 轮，Prodigy Schedule-Free |
| dots.tts | 语言模型和扩散头上的 LoRA（秩 32） | 4 轮，Prodigy Schedule-Free |
| GPT-SoVITS v2Pro / v2ProPlus | 两个模型全量微调，先 SoVITS 后 GPT，与网页界面相同 | 8 + 15 轮 |
| GPT-SoVITS v4 | SoVITS 扩散模型上的 LoRA，然后 GPT 全量微调 | 8 + 15 轮 |

- 「停止」会先保存检查点；之后可以从该步继续，「继续训练到」可以给已完成的任务加训更多步数。
- 「进度」显示损失曲线（每张图都可以折叠）、学习率，以及用从训练集中留出的片段得到的验证损失和
  每个检查点的试听样本。「试听」会在「合成」页打开该检查点。
- **说话人相似度**：用 CAM++ 说话人嵌入给每个样本与训练集声音的相似程度打分，并与训练集真实片段的
  得分对照，帮你挑出最像本人的检查点。
- **优化器**：Prodigy Schedule-Free
  （[prodigy-plus-schedule-free](https://github.com/LoganBooker/prodigy-plus-schedule-free)）
  会为模型的每个部分自行确定步长，学习率只是一个倍数（1）。也可以选择带余弦调度的 AdamW 或 Prodigy。

训练任务保存在 `lora/<模型>/<名称>/`（`voxcpm`、`dots_tts` 或 `gpt_sovits`）。VoxCPM 自带的
`lora_ft_webui.py` 训练的任务使用相同的结构，也会出现在列表中，并且可以继续或加训。直接放在
`lora/` 下的任务和音色（来自旧版本，或手动复制进来的）会在服务器启动时移到对应模型的文件夹中。

## 速度

合成和训练都走为本项目专门优化的路径。每一项都与原始代码对照验证过：训练的损失曲线一致；合成的
输出在浮点舍入误差范围内一致（说话人相似度和识别结果相同），所以提速不以质量为代价。以下数据在
一张 16 GB 的 NVIDIA 显卡上测得；对比基准是模型自己的代码，没有的则是普通的 PyTorch 循环：

| | 做了什么 | 提升 |
|---|---|---|
| 切换音色（VoxCPM2、dots.tts） | 任意秩的 LoRA 直接写入已加载、已编译的模型 | 约 1 秒，而不是 30–40 秒的重新加载 |
| dots.tts 合成 | 编译模型；每个解码步以 CUDA Graph 重放 | 快约 4 倍 |
| GPT-SoVITS 合成 | GPT 的解码步做成一个带静态缓存、融合了层计算的 CUDA Graph；v4 的扩散模型经过编译 | 快约 2.5 倍（v2Pro / v2ProPlus），1.3 倍（v4） |
| VoxCPM2 训练 | 冻结权重用 bfloat16 存储（显存减半，16 GB 能跑批大小 4）；每个片段的音频只编码一次；Transformer 层融合 | 每步快约 1.6 倍；8 GB 显卡快 2.3 倍 |
| dots.tts 训练 | 每个片段只编码一次并缓存到磁盘；不计算词表 logits；层融合 | 每步快约 3 倍 |
| GPT-SoVITS 训练 | 去掉逐参数的 GPU 同步；特征按片段缓存在数据集中；v4 的扩散块经过编译 | 每步快约 1.2 倍；几秒内开始训练 |
| 准备数据集 | 人声分离模型经过编译；语音检测和说话人嵌入在 GPU 上批量计算 | 人声分离 2 倍，语音检测 3.5 倍，「其他声音」检查约 10 倍 |

每次加载模型时编译需要一点时间（第一次运行填充缓存时更久）；设置 `POLYVOX_OPTIMIZE=0` 可以关闭编译。

## 分享音色

在「音色」面板中选中一个音色，点「导出」。LoRA 的 zip 包只包含权重（默认 bfloat16：体积减半，
输出不变）、以 Hugging Face id 记录基础模型的配置，以及一份使用说明。GPT-SoVITS 音色会以 GPT-SoVITS
网页界面的格式导出两个模型，并附上参考音频及其文本。本地路径、优化器状态、日志和数据集音频都不会包含在内。

「音色」面板中的「导入」可以添加这样的 zip 包。「GPT-SoVITS…」可以导入在 GPT-SoVITS 网页界面中训练的
一对权重（v2、v2Pro、v2ProPlus 或 v4），参考音频可以取自数据集或文件。

## 运行要求

Windows 或 Linux。[uv](https://docs.astral.sh/uv/) 会在首次运行时安装 Python 3.13、PyTorch 和其他
所有依赖，`run.bat` / `run.sh` 会为本机选择合适的 PyTorch 版本（可用 `POLYVOX_TORCH` 指定）：

| 版本 | 适用于 |
|---|---|
| `cu130` | NVIDIA RTX 20 系列及更新（包括 RTX 50），驱动支持 CUDA 13 |
| `cu126` | 较旧的 NVIDIA 显卡（如 GTX 10 系列）或驱动（CUDA 12.6） |
| `rocm` | Linux 上的 AMD 显卡（ROCm 7.2：较新的 Radeon 和 Instinct；未经测试） |
| `cpu` | 没有显卡：可以准备数据集，但合成很慢，训练不现实 |

能做什么取决于显存大小；程序会据此选择批大小以及哪些模型共用显卡：

| 显存 | 合成 | 训练 | 准备数据集 |
|---|---|---|---|
| 16 GB 及以上 | 可以 | 可以 | 所有模型常驻 |
| 12 GB | 可以；准备数据集时卸载 | 可以；部分模型使用梯度检查点（较慢） | 较小的批 |
| 8 GB | 可以；参考音频降噪在 CPU 上运行 | 可以，使用梯度检查点（较慢） | 显卡上一次只放一个模型 |
| 8 GB 以下 | 不可以（需要约 8 GB） | 不可以 | 与 8 GB 相同 |

显存较小时等效批大小不变，所以只是训练更慢，结果并无不同。仍然显存不足的批会对半拆分重试。
如果训练和合成用同一张显卡，开始训练时会卸载合成模型；想边训练边合成，可以把它们放在不同的显卡上
（例如 `POLYVOX_DEVICE=cuda:1`）。

无需安装 FFmpeg：其他格式的音频（m4a、视频文件）由自带 FFmpeg 的 PyAV 解码。在 Linux 上，
Triton（用于编译模型）需要 C 编译器（`apt install build-essential`）。

要从另一台电脑访问，请用 `./run.sh --host 0.0.0.0` 启动。它没有登录功能：只在可信的网络中使用，
或通过 SSH 隧道访问。

## 模型

「模型」页列出程序用到的每个模型及其大小、许可证和下载状态，并把缺少的模型带进度地下载到
`models/`。只有 VoxCPM2 是必需的，其他模型按需下载：

| 模型 | 用途 | 大小 |
|---|---|---|
| VoxCPM2 | 合成和 LoRA 训练 | 5 GB |
| dots.tts SOAR | 合成和 LoRA 训练 | 4.9 GB |
| GPT-SoVITS v2Pro / v2ProPlus、G2PW | 合成和音色训练（G2PW：中文多音字读音） | 1.7 + 0.6 GB |
| GPT-SoVITS v4 | 48 kHz 的合成和音色训练 | 0.8 GB |
| Qwen3-ASR 1.7B | 转写、切分、与语音识别对比 | 4.1 GB |
| Qwen3-ForcedAligner 0.6B | 切分和检查片段 | 1.9 GB |
| wav2vec2 中文 | 检查用的第二个对齐模型 | 1.3 GB |
| CAM++、ZipEnhancer、AST | 说话人相似度和「其他声音」；参考音频降噪；唱歌检测 | 0.4 GB |
| RoFormer 人声分离 / 去混响 / 降噪 | 可选的「清理」步骤 | 各 0.9 GB |

下载来源可以是 Hugging Face、它的镜像（hf-mirror.com 或任意地址；`POLYVOX_HF_ENDPOINT` 设置服务器
默认值）或 ModelScope，只下载用到的文件，中断后可以续传。服务器运行期间下载的模型会在下次加载时
使用，无需重启。没有下载的 Hugging Face 模型也能用：第一次加载时会下载到 Hugging Face 缓存
（不显示进度）。

## 配置

环境变量，均为可选：

| 变量 | 默认值 | |
|---|---|---|
| `POLYVOX_MODELS_DIR` | `models` | 下载的模型 |
| `POLYVOX_HF_ENDPOINT` | | 下载用的 Hugging Face 镜像，例如 `https://hf-mirror.com` |
| `POLYVOX_LORA_DIR` | `lora` | 训练任务、LoRA 和音色 |
| `POLYVOX_DATA_DIR` | `data` | 数据集 |
| `POLYVOX_DEVICE` | `auto` | 合成设备：`cuda`、`cuda:1`、`cpu`…… |
| `POLYVOX_TRAIN_GPU` | | 训练用的 CUDA 设备编号（默认：第一张显卡） |
| `POLYVOX_ASR_DEVICE` | `auto` | 语音识别和对齐的设备；`auto` = 与合成相同 |
| `POLYVOX_VRAM_GB` | | 最多使用这么多显存（显卡与其他程序共用时），并按此选择设置 |
| `POLYVOX_OPTIMIZE` | `auto` | 用 Triton 编译模型（`torch.compile`）；`auto` = 使用 CUDA 时开启 |
| `POLYVOX_DENOISER` | `1` | 加载 ZipEnhancer，为参考音频降噪 |
| `POLYVOX_MODEL` | `openbmb/VoxCPM2` | VoxCPM2：本地文件夹或 Hugging Face id |
| `POLYVOX_DOTS_MODEL` | `rednote-hilab/dots.tts-soar` | dots.tts：本地文件夹或 Hugging Face id |
| `POLYVOX_GSV_MODEL` | （已下载的副本） | GPT-SoVITS：结构与 `lj1995/GPT-SoVITS` 相同的文件夹（v2Pro、s1v3.ckpt、编码器） |
| `POLYVOX_GSV_G2PW_MODEL` | （已下载的副本） | GPT-SoVITS：G2PW 文件夹 |
| `POLYVOX_GSV_V4_MODEL` | （已下载的副本） | GPT-SoVITS v4：包含 `s2Gv4.pth` 和 `vocoder.pth` 的文件夹 |
| `POLYVOX_ASR_MODEL` | `Qwen/Qwen3-ASR-1.7B-hf` | 语音识别模型 |
| `POLYVOX_ALIGN_MODEL` | `Qwen/Qwen3-ForcedAligner-0.6B-hf` | 强制对齐模型 |
| `POLYVOX_CTC_ALIGN_MODEL` | `jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn` | wav2vec2 CTC 对齐模型（单一语言） |
| `POLYVOX_DENOISER_MODEL` | `iic/speech_zipenhancer_ans_multiloss_16k_base` | 降噪模型的文件夹或 ModelScope id |

`run.bat` / `run.sh` 使用项目自己的 `models/`、`lora/` 和 `data/`；设置这些变量即可改用其他文件夹。
